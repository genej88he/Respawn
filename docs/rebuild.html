Respawn Rebuild

Respawn keeps backups of your game saves so you can go back in time. This page tracks rebuilding it into an app real people can install, and then adding cloud backup.

Now: Phase 1

Motivation

Why this project

The goal

Respawn is Gene's one main portfolio project for summer 2027 internships. It should show real experience building something with real users and real workloads.

  • Backend / software engineering roles
  • Systems and embedded Linux roles

The advice behind it

An Amazon engineer said the best way for an intern to stand out is to build apps with real users (friends count), learn cloud, deployments, automated testing and beta/staging stages, and practice system design by designing each project yourself.

The rules we follow

  • One finished project with real users beats several half-finished ones.
  • Never make up numbers. Resume lines come only from things we measured.
  • No emulator inside Respawn. It's a save backup tool.

App improvement logic

Why we're changing how it's built

What the app does for you stays the same. The rebuild fixes five problems that would block real users and cloud backup.

One boss for the dataToday the screen keeps the game list and Python keeps the backups, and they can disagree. The backend will handle both.
Never lose a saveRestore deletes your save before copying the backup in. If that fails halfway, the save is gone. We'll copy first, then swap.
See every errorA failed restore still says "done" today. Errors will show up on screen.
Easy for friendsToday every user needs Python installed. The new app is one language and a normal installer.
Ready for the cloudCloud backup needs one place that knows about every game and backup. That's the new backend.
